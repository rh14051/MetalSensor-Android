# سنسور فلز — Metal Sensor

اپلیکیشن اندروید اختصاصی تست و تیونینگ (tuning) سنسور مغناطیسی تشخیص خودرو که به **ESP32-C3** از طریق **BLE** متصل می‌شود. هدف: تغییر پارامترهای تشخیص **بدون کامپایل مجدد فریمور** و دیدن لحظه‌ای رفتار سنسور.

---

## ۱) مشخصات فنی اپ

| مورد | مقدار |
|---|---|
| زبان / UI | Kotlin + Jetpack Compose (Material 3) |
| حداقل اندروید | 8.0 (minSdk 26) — targetSdk 34 |
| معماری | تک‌اکتیویتی، MVVM ساده، بدون DI |
| BLE | کتابخانه **Nordic Android BLE Library** (`no.nordicsemi.android:ble-ktx:2.9.0`) |
| نمودار | Canvas سفارشی Compose (بدون وابستگی اضافه) |
| ذخیره‌سازی | SharedPreferences (آخرین دستگاه + آخرین پارامترها) |
| زبان رابط | فارسی، RTL (اجباری در سطح Compose، مستقل از زبان سیستم) |
| تم | دنبال سیستم + رنگ داینامیک Material You (اندروید 12+) |

### قابلیت‌های کلیدی

- اسکن BLE با فیلتر نام `CAR-` و نمایش RSSI
- اتصال با یک کلیک + **اتصال خودکار به دستگاه ذخیره‌شده در اجرای بعدی**
- **اتصال مجدد خودکار** هنگام قطعی با فاصله افزایشی (۲، ۴، ۸ ثانیه… حداکثر ۱۰ ثانیه) با دکمه لغو
- داشبورد زنده: دلتا درشت، نشانگر وضعیت رنگی (CAL خاکستری / CLEAR سبز / DETECTING زرد / OCCUPIED قرمز)، Baseline
- نمودار ۶۰ ثانیه‌ای دلتا با **دو خط آستانه ON و OFF** (محدودیت ۳۰۰ نقطه)
- بخش تاشو داده خام X/Y/Z + سوییچ RAW
- صفحه تیونینگ: ۵ پارامتر با دکمه «اعمال» مجزا، **تأیید با `OK=` و خطای Toast بعد از ۲ ثانیه بدون پاسخ**
- هشدار نارنجی (بدون جلوگیری از ارسال) وقتی `THRESHOLD_OFF > THRESHOLD_ON`
- دکمه‌های «شروع کالیبراسیون» (CAL) و «ریست Baseline» (RS)
- **ثبت CSV دستی** (شروع/توقف) + اشتراک‌گذاری فایل برای تحلیل در اکسل
- ذخیره خودکار پارامترها هنگام «اعمال» در SharedPreferences

## ۲) ساخت (Build)

1. **Android Studio** (نسخه Koala یا جدیدتر، JDK 17 — JBR خود Studio کافی است)
2. پوشه `MetalSensor` را باز کنید (Open) و صبر کنید Sync تمام شود
3. `Build > Make Project` یا مستقیم Run روی دستگاه (اپ BLE است، روی شبیه‌ساز کار نمی‌کند)

اگر wrapper جار خطا داد، از ترمینال Android Studio:

```bash
gradle wrapper --gradle-version 8.9
```

### مجوزها (خودکار)

- اندروید 12+: `BLUETOOTH_SCAN` + `BLUETOOTH_CONNECT` (رانتایم)
- اندروید 11 و پایین‌تر: `ACCESS_FINE_LOCATION` (رانتایم — سرویس Location باید روشن باشد)

## ۳) پروتکل BLE

- **Service**: `0000FFE0-0000-1000-8000-00805F9B34FB`
- **RX (نوشتن به دستگاه)**: `FFE1` — WRITE
- **TX (گرفتن از دستگاه)**: `FFE2` — NOTIFY
- فرمت: خط متنی، خاتمه با `\n` — اپ یک **بافر خطی** دارد و پکت‌های تکه‌تکه/چندخطی BLE را به‌درستی تجمیع می‌کند.
- اپ در لحظه اتصال MTU را ۲۴۷ درخواست می‌کند تا پیام بلند `A=...` در یک پکت جا شود.

### فرمان‌ها (اپ → ESP32)

| فرمان | مثال | توضیح |
|---|---|---|
| `ON=` | `ON=400\n` | THRESHOLD_ON |
| `OFF=` | `OFF=250\n` | THRESHOLD_OFF |
| `ONT=` | `ONT=2500\n` | ON_TIME_MS |
| `OFFT=` | `OFFT=4000\n` | OFF_TIME_MS |
| `ALPHA=` | `ALPHA=0.004\n` | BASELINE_ALPHA (0 < α ≤ 1) |
| `CAL` | `CAL\n` | شروع مجدد کالیبراسیون |
| `RS` | `RS\n` | ریست Baseline به لحظه فعلی |
| `SHOW` | `SHOW\n` | شروع ارسال مداوم + پاسخ `A=` |
| `HIDE` | `HIDE\n` | توقف ارسال مداوم |
| `RAW` / `NRAW` | `RAW\n` | فعال/غیرفعال کردن داده خام X/Y/Z |
| `SCAN` | `SCAN\n` | اسکن کامل باس I2C → پاسخ `I=SCAN:...` |
| `ADDR=` | `ADDR=0x2C\n` | تعیین دستی آدرس I2C (پشتیبانی هگز و دهدهی؛ `ADDR=AUTO` برای حالت خودکار) |

### پیام‌ها (ESP32 → اپ)

| پیام | مثال | توضیح |
|---|---|---|
| `D=` | `D=1234` | دلتای فعلی (هر 200ms هنگام استریم) |
| `S=` | `S=CLEAR` | وضعیت: CAL / CLEAR / DETECTING / OCCUPIED |
| `B=` | `B=1234,-567,890` | Baseline فعلی |
| `R=` | `R=100,-200,50` | داده خام X,Y,Z (فقط با RAW) |
| `A=` | `A=400,250,2500,4000,0.004` | همه پارامترها (پاسخ SHOW / بعد اتصال) |
| `OK=` | `OK=ON` | تأیید فرمان |
| `ERR=` | `ERR=ALPHA_RANGE` | خطا |
| `I=` | `I=CHIP:QMC5883P/QMC6310@0x2C` | اطلاعات چیپ شناسایی‌شده / نتیجه اسکن (در کنسول فرمان اپ نمایش داده می‌شود) |

> اپ بعد از اتصال، خودکار `SHOW` می‌فرستد تا فیلدهای تیونینگ با مقادیر واقعی دستگاه پر شوند و نمودار فوراً شروع به حرکت کند.

## تشخیص خودکار سنسور (v1.1)

ماژول‌های GY-271 در دو نسل ساخته می‌شوند و هر دو به‌صورت خودکار شناسایی می‌شوند:

| چیپ روی برد | آدرس I2C | پروتکل داخلی |
|---|---|---|
| QMC5883P / QMC6310 (نسل جدید) | **0x2C** (گاهی 0x1C) | دیتا از رجیستر 0x01، little-endian |
| QMC5883L کلاسیک | 0x0D | دیتا از رجیستر 0x00، little-endian |
| HMC5883L اصلی (Honeywell) | 0x1E | دیتا از 0x03، big-endian، ترتیب X-Z-Y |

- اگر اسکنر I2C شما آدرس `0x2C` را نشان داد یعنی چیپ ماژول از نسل جدید است (برخلاف برچسب GY-271)؛ اسکچ v1.1 آن را خودکار می‌شناسد و نیازی به هیچ تغییری نیست.
- با فرمان `SCAN` (کنسول فرمان اپ) لیست همه دستگاه‌های روی باس را ببینید و با `ADDR=` آدرس را دستی قفل کنید.
- اگر اتصال سنسور وسط کار قطع/وصل شود، دستگاه هر ۲ ثانیه دوباره جستجو می‌کند و پس از پیدا شدن، کالیبراسیون را خودکار تکرار می‌کند.
- **LED روی GPIO4**: هنگام DETECTING و OCCUPIED روشن می‌شود (بلافاصله بعد از عبور از آستانه).

## ۴) فریمور ESP32-C3

اسکچ کامل در `esp32/metal_sensor_esp32c3/metal_sensor_esp32c3.ino` — **بدون هیچ کتابخانه اکسترنال** (فقط بورد ESP32 لازم است).

### سیم‌کشی QMC5883L (پیش‌فرض)

| QMC5883L | ESP32-C3 SuperMini |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SDA | GPIO 8 |
| SCL | GPIO 9 |

- پین‌ها با `I2C_SDA` / `I2C_SCL` بالای فایل قابل تغییرند.
- **تست بدون سنسور**: `SENSOR_TYPE` را به `SENSOR_TYPE_SIM` تغییر دهید — داده شبیه‌سازی‌شده (عبور خودروی فرضی هر ~۲۵ ثانیه) تولید می‌شود تا اپ و پروتکل را تست کنید.
- LED وضعیت اختیاری: `LED_PIN` را به شماره GPIO تغییر دهید (=-1 خاموش).
- نام BLE دستگاه: `CAR-SENSOR` (با ثابت `DEVICE_NAME`).
- پارامترها در NVS ذخیره می‌شوند و بعد از ریست حفظ می‌شوند.

### منطق سنسور

- دلتا = جمع قدرمطلق اختلاف با Baseline (L1): `|x-bx|+|y-by|+|z-bz|`
- Baseline با EMA (ضریب ALPHA) فقط در حالت **CLEAR** به‌روز می‌شود (وقتی خودرو حاضر است فریز می‌شود)
- `CAL`: میانگین‌گیری ۲ ثانیه‌ای → CLEAR
- هیسترزیس: CLEAR→DETECTING با `TH_ON`، تأیید با `ON_TIME_MS` → OCCUPIED؛ خروج با `TH_OFF` پایدار به مدت `OFF_TIME_MS`

## ۵) نکات و عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| دستگاهی در اسکن نمی‌آید | اندروید 11 به پایین: Location روشن باشد. اندروید 12+: مجوز «Nearby devices» را بدهید. نام دستگاه باید با `CAR-` شروع شود |
| اتصال قطع می‌شود | اپ خودش ریکانکت می‌کند (تلاش‌ها بالای صفحه دیده می‌شود). برد/آنتن را از منبع RF دور کنید |
| `A=` (پارامترها) نمی‌آید | MTU — اپ خودش 247 درخواست می‌کند؛ فریمور `setMTU(135)` دارد. فریمور را آپدیت کنید |
| مقدار اعمال نمی‌شود | پیام «پاسخی دریافت نشد» یعنی `OK=` نیامد — چک کنید فریمور همان پروتکل را پیاده کرده |
| فایل CSV کجاست؟ | `Android/data/com.metalsensor.app/files/logs/` یا دکمه اشتراک‌گذاری کنار دکمه ثبت |
| فیلدها خالی‌اند در شروع | بعد از اتصال SHOW خودکار ارسال می‌شود؛ دکمه SHOW را هم دستی دارید |
